# 只读面板

```bash
# .env
WEB_ENABLED=true
WEB_HOST=127.0.0.1        # 默认只听回环；要局域网访问改 0.0.0.0
WEB_PORT=8787
```

打开 `http://127.0.0.1:8787/`：一屏看完"每个账号现在怎么样"。

## 面板内容

- **LED 状态阵列**：24 格按状态计数分配（正常 / 失败 / 长期无更新 / 从未有作品 /
  已移除），小类别保底 1 格——100 个账号里那 1 个在失败的，不会被舍成 0 格而看不见
- **数据条**：账号总数、正常、请求失败、长期无新作品、从未有作品、已移除
  （最后一项只在真有账号被移出 `users.conf` 时出现）
- **账号列表**：状态徽章、更新频率（悬停看"基于最近 N 条非置顶作品，平均 X 天/条"）、
  已知作品数、**距最新作品发布多久**（看的是作品的发布时间，不是"上次检测到
  变化"的时间——后者会被一次删除/改名刷新）；整行可点，手机上按起来不费劲
- **详情弹窗**：已知作品（置顶的排最前，含类型、缺席轮数）、已消失作品
  （含消失原因）、最近事件、以及最新作品发布时刻 / 更新频率 / 首次记录 / 累计轮次 /
  最近一次错误码

## 页面顶部的两个轮次数，口径不同

- **本次运行第 N 轮**——这次进程启动以来跑了多少轮（内存计数）。**重启就从头数**，
  所以它小不代表丢数据
- **累计 M 轮**——状态库里累计记录了多少轮，跨重启、也不受 `ROUNDS_KEEP_DAYS`
  裁剪影响（取的是 SQLite 的自增号段，不是行数）
- 详情弹窗里的「累计轮次」是第三个口径：**这个账号**被检查过的轮数（`authors.runs`）

上游闸门关闭时，页面顶部会出现红色警示条，与通知里的"本轮整体跳过"是同一件事。

## 只读、无鉴权、不消耗身份

面板列表读 `data/status.json`（每轮写一次的快照），详情读状态库，**不发任何
上游请求**。所以打开它不消耗 DTK 身份、不会触发风控。**要对外暴露请自己加反代
鉴权**——面板本身没有登录页。

## 移动端

小屏（手机）下布局会自动重排：状态单独一行、账号名整行，上游地址与 PID 不占位置；
详情变成底部抽屉，内容长的时候整页滚动，并留出 iPhone 底部安全区。

## 机器接口

| 路径                          | 用途                          |
| ----------------------------- | ----------------------------- |
| `/api/state`                  | 快照原文                      |
| `/api/health`                 | 小结                          |
| `/api/user/<sec_user_id>`     | 单账号详情                    |
| `/metrics`                    | Prometheus 格式               |
| `/healthz` `/readyz`          | 探针                          |
