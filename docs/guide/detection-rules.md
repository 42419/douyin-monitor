# 判定规则

## 新作品

本页出现、本地没记录过、也不在 tombstone（已消失记录）里 → 推送。首次见到一个
账号时只记录**不推送**（否则上线一个新账号会被历史作品刷屏）。

## 作品消失（分级确认）

| 类型             | 连续几轮不在本页才确认    |
| ---------------- | ------------------------- |
| 普通作品         | 2（`DELETE_CONFIRM_ROUNDS`） |
| 置顶作品         | 3（`DELETE_CONFIRM_ROUNDS_TOP`） |
| 全部作品同时消失 | 3（`DELETE_CONFIRM_ROUNDS_ALL`，并在通知里附核实提醒） |

确认前只累计计数，不发任何通知；中途回来则计数清零。

**"被新作品挤出窗口"不算消失**：窗口整体前移了多少，就最多有多少条能用挤出解释，
这些走静默清理并写 tombstone——于是它们将来若因窗口回移重新出现，也不会被当成
新作品重复推送（对应事件类型 `scrolled_out`）。

## 漏检

抖音接口返回的是 `count + 本页置顶数` 条，所以"条数达到 count"不等于被截断。
dywatch 改用**时间连续性**判断：本页**非置顶**作品里最旧的发布时间，比上一轮
非置顶作品里最新的发布时间还新 → 中间必然有没采集到的作品，于是告警建议调大
`FETCH_COUNT`（对应事件 `gap_detected`）。

## "作者 ID 写错了"怎么发现

见 [监控列表 users.conf](/guide/users-conf#作者-id-写错了怎么发现)。

## 置顶标志从哪来

DTK 的归一化结果不暴露置顶标志，只有 `include_raw=true` 时 `raw.is_top` 才有
值——**而且只有作品列表接口有效，详情接口的 `is_top` 恒为 0**。带 raw 会让响应
体积约 ×3，所以默认只在"发现新作品 / 标题变化 / 每 `RAW_REFRESH_ROUNDS` 轮"
时带一次，由 `INCLUDE_RAW` 控制（`auto` / `always` / `never`）。
